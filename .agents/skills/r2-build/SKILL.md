# 핵심 흐름 구현

- 현재 코드·합의된 요구에서 이어가며 기존 도구로 입력→처리→출력을 먼저 완성한다.
- 저장 요구가 있으면 다시 읽기까지 확인한다. 고정 응답·가짜 성공으로 실제 기능을 대신하지 않는다.
- 새 의존성·화면·DB는 필요성이 있을 때만 추가한다.
- 새 기능에는 핵심 동작 테스트를 최소 한 개 추가·실행한다. 변경 파일·실행 방법·검증 결과·미확인을 전달한다.
- 웹 서버는 `0.0.0.0`과 실제 포트를 사용한다. 화면은 사용자가 내부 Browser에서 확인하고 서버 터미널은 유지한다.
